# 通用图像预处理流程的离线对比

调研日期：2026-11-12。范围：在不按图调参、不做局部遮罩的前提下，用一套固定、便宜的整图处理，减少照片转拼豆时暗部塌成一片黑、白色偏黄这类问题。

本文是离线试验记录，不是已实现功能，也不是已验证的默认值。

## 现状

`src/core.ts` 的 `quantize` 先把每个像素按 RGB 欧氏距离映射到色板最近色。颜色种类超过上限时，按出现次数保留前 N 种，再重新映射。`src/main.ts` 默认不勾选平滑缩放，所以缩小图片时是最近邻取样。

## 试验设置

- 两张维护者自备的猫照片。一张有低彩度的深色虹膜，一张有大面积白毛和灰色针织物。照片不在仓库内，也不公开。
- 色板为 Artkal C（174 色），颜色上限 24，长边不超过 256。
- 三套方案各自独立搜索。每套都用同一组参数处理两张图，并把两张图的得分合起来选参数。搜索没有使用眼睛等局部区域，局部区域只作事后读数。
- 每套搜索约 94 至 360 次量化，属于一次性离线成本。

## 推荐流程（维护者已在两张图上认可）

每张图使用相同步骤和常数：

1. 用 Lanczos 缩到目标网格。网格尺寸是珠子预算，不由该流程决定。
2. 白平衡：在 640 像素缩略图上取各通道第 99 百分位作为白点，在线性光下按一半强度校正。
3. 色调：线性光 gamma 0.65 提亮暗部；在 OKLab 明度上做局部对比增强，系数 0.6，参照为 3 格高斯模糊；OKLab 色度乘 1.4，色相不变。
4. 选色与映射：在 OKLab 中用加权贪心 k-medoids 从色板选出 24 色，再把每格映射到最近的已选色。不抖动。

使用时每张图只量化一次。在试验机器上，160 至 256 宽约 0.25 至 0.4 秒。

## 观察结果

| 现象 | 当前实现 | 推荐流程 |
| --- | --- | --- |
| 深色虹膜所在的眼睛 | 与周围暗毛连成一片黑色 | 能看出瞳孔、高光与眼眶；虹膜为灰褐色，不是原图观感上的绿色 |
| 虎斑与暗部纹理 | 大面积塌成黑色 | 条纹和明暗层次可见 |
| 大面积白毛 | 偏卡其色 | 白色或近白色 |
| 粉色鼻子 | 偏暗红 | 偏橙褐色，仍不是粉色 |
| 浅黄墙面 | 保留黄色 | 黄色明显减弱 |

单独更换映射颜色空间（RGB、CIE Lab、OKLab、加权 OKLab），几乎不改变上述现象。起作用的主要是映射前的整图明暗处理。

## 未采用的做法

- 只换颜色空间：效果很小。
- 最近邻缩放：结构保留明显差于面积平均、三次和 Lanczos。
- Floyd–Steinberg 抖动：在珠子尺度上产生杂点。
- 全强度白平衡或灰度世界白平衡：画面整体褪色或偏色。
- 按明度加权放大暗部色度并旋转色相：能让虹膜变绿，但同时让毛球偏砖红、虎斑出现绿斑、鼻子偏品红，白毛也回到奶油色。它的常数是在这两张图上凭眼调的，过拟合风险高。
- 只处理眼睛或其他局部区域的遮罩：不符合“与对象无关”的要求。

## 局限

- 只有两张图，无法说明对其他照片同样有效。
- 判断依据是维护者看整图的主观评审，不是客观精度。
- 本文不改变现有的 24 色上限、评分门槛或搜索轮数。它们仍是待校准的项目约定。
- 尚未实现到应用中，也未验证浏览器内的耗时。
