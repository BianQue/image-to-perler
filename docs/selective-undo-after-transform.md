# 结构变换后的选择性撤销：首版恢复范围

2026-11-12，Asia/Taipei。设计待解问题 2 的 Proposed 研究结果。只记录恢复范围、模型与验收要求，不实现应用功能。

## 结论

首版采用统一的操作记录与补偿引擎，但不承诺所有操作都能自动选择性撤销。对之前的局部修改，旋转或翻转后可自动恢复未被后续修改的格子；裁剪后只恢复仍存在且未被修改的格子；换色板后先报冲突并给预览。这里的“自动”指通过安全检查后无需逐格解决冲突，不代表跳过用户提出撤销的意图。

“所有数据修改共用一套记录”是可以保留的统一设计。需要区分的是普通撤销与选择性撤销。普通撤销可以整份回到旧快照。选择性撤销必须保留后续已提交的人工效果，快照本身不能决定哪些内容该保留。快照加具体操作日志重放也是可行方案，并不与补偿记录互斥。

首版规则是：从目标操作的实际写集出发，把其前像沿后续坐标映射移到当前图纸；项目与色板必须兼容，目标格必须仍存在，逐格版本必须仍等于目标操作写完时的版本。恢复颜色与制作标记这一整对值，并写入新的版本。任何检查不满足都要给出冲突原因。部分恢复不能显示“全部已撤销”。

## 这次采用的设计方法

先定保留的对象，再谈逆操作。要保留的是人的实际笔迹，还是人在旧上下文下发出的条件命令？下面的 Replace 反例表明，这不是措辞差别，而是两种不同结果。

接着把“统一记录”与“统一成功”分开。所有数据修改都要记录，这是完整性要求；哪些记录能安全变成当前补偿，这是可定义性与冲突策略。支持不了的操作也要留下屏障，不能不记。

再检查组合关系，而不只检查操作自身是否可逆。对几何双射 T 和一次局部编辑 E，成立的是 `T ∘ E(S,c) = E(T(S),c) ∘ T`。这称为随坐标映射保持等价，不是说用原坐标直接交换两个操作。裁剪只在剩余定义域内保留这条关系。色板还改变值域，必须连 completed 一起推导。

最后用独立参考重放和故意错误变体检验结论。正向通过只说明给定边界内没找到反例，见证还要证明成功与部分恢复确实发生。此次方法产生了一个必要修正：“删掉一步重放”的验收条件需要先写清重放语义。

## 必须先确定“保留后续操作”的含义

本模型验证的是保留后续**已提交的具体效果**。例如一条“替换同色”最终改了哪些格子，就记录这些格子的前后值。重放这些值，不重新计算当年的颜色筛选条件。制作标记也重放当时的最终布尔值，不重新执行 toggle。

验收语句必须明确重放对象。不能无条件说“等于删掉目标操作后重新执行全部旧命令”。已有一个通过 TLC 找到的反例，而且无逐格写冲突：

1. 初始格 1 是 A，完成标记为 true。
2. Agent 把格 1 画成 B，标记被清除。
3. 人把所有 A 替换为空。此时格 1 是 B，不在人的写集内。
4. 撤销 Agent，恢复格 1 的 A 与 true，保留人实际擦掉的其他格子。

如果删掉第 2 步后重新执行“把所有 A 替换为空”，第 3 步就会额外擦掉格 1。两种答案不同。`SelectiveUndoWitnessReadDependency` 确认这种差异确实可达。真实源码检查还复现了 floodFill 因区域连通性改变而出现的同类差异。

因此本轮的 `CorrectInverse` 明确等于**从初始状态重放已提交效果、略过目标局部操作**，在无冲突时比较整张图的颜色与完成标记。部分恢复只比较安全子集，同时验证其余当前内容完全不变。如果产品要保留的是后续命令的条件性意图，就必须再记录读集、区域连通性依赖及条件变化，遇到依赖时报冲突。本轮没有证明后一种契约。

## 首版逐项决定

下表是拟议首版能力，不是现有应用已具备的功能。所有“自动恢复”均受项目、色板、映射及版本检查约束。

| 选择性撤销的目标与后续历史 | 首版决定 | 范围与证据 |
|---|---|---|
| paint、擦除、选区填充、笔画等具体局部写集，后来只有 rotate 或 flip | 自动恢复；若部分格另被编辑，则部分恢复 | 映射后的颜色与 completed 一起恢复。模型包含 Paint、Replace、Done；其他工具须先归一化并验收 |
| fill、替换同色、去孤点的已提交具体写集，后来 rotate 或 flip | 与局部补丁相同 | 不重新求连通区或颜色条件。若要求保留命令意图而不是已提交效果，先冲突加预览，等待读依赖支持 |
| 制作标记，后来 rotate 或 flip | 自动恢复或部分恢复 | 同格后来改色或改标记即冲突，不因只涉及一个字段而绕过一致性单元 |
| 上述局部操作，后来 crop 或缩小尺寸 | 保留区自动恢复；删除区冲突。二者都有时为部分恢复 | 没有删除区目标就不能伪称恢复成功，也不能顺便扩大画布 |
| 上述局部操作，后来换色板 | 冲突加预览 | 首版色板 epoch 是保守屏障，不论该次映射碰巧是否单射 |
| 局部操作发生在换色板以后，后来未再次换板 | 自动恢复或部分恢复 | 前后色号已属于当前色板，按普通局部规则处理 |
| 同格后来改过又改回原值 | 冲突加预览 | ABA。值相同但版本不同仍拒绝 |
| rotate 或 flip 操作本身作为被撤销目标，且后面还有编辑 | 冲突加预览 | 本模型没有开放此类选择性撤销。不能拿局部逆跨旋转的证明来证明旋转自身的逆 |
| crop、resize 或换色板本身作为被撤销目标 | 冲突加预览 | 需考虑尺寸恢复、删除区、后来新增色及整个结构事务。普通栈顶快照撤销不受此项限制 |
| 选区移动本身 | 首版先冲突加预览 | 将源区与目标区归一化为完整事务后可扩展为局部补丁；本轮不承诺已经验证 |
| 新建、导入、打开另一项目后试撤旧局部操作 | 冲突加预览，不自动跨项目恢复 | ProjectReplace 已建模；现实中需用不可混淆的 projectId 与 epoch |
| 项目名、boardSize 的选择性撤销 | 本轮不开放，冲突加预览 | 可用同一事务记录框架扩展字段版本，不属于逐格证明 |

## 模型中的恢复算法

模型在 [formal/SelectiveUndo.tla](formal/SelectiveUndo.tla)。初始图是 3×2，0 代表空格，1、2 代表两种非空颜色。初始存在一格 completed=true，也存在空格和待合并颜色。每格包含颜色 c、完成标记 d、版本 v 与参考身份 id。

生产式路径 `Lift` 组合目标操作之后的全部结构坐标映射。rotate 的旧坐标 `(x,y)` 在新宽度 `h` 下变成 `(h-1-y,x)`；flipH 变成 `(w-1-x,y)`；flipV 变成 `(x,h-1-y)`。crop 把被删坐标映射成无目标，模型以 0 表示。

`SelectiveUndo(k)` 对实际写集逐格检查：

1. 目标是支持的局部操作，而且没有被本模型处理过。
2. 项目 epoch 和色板 epoch 兼容。
3. 组合坐标映射有当前目标。
4. 该格版本仍等于操作 k 的 after 版本。
5. 将 before 的颜色与 completed 写成一个新的补偿事务，使用新的版本，不回滚版本计数。
6. 为不能恢复的每格保留原因与冲突。返回 success、partial 或 conflict。

真正实现必须在串行提交队列里重新检查后再提交。预览到确认之间若发生新修改，旧预览不构成写入授权。成功响应还必须满足待解问题 1 的持久化确认协议；本模型不重新证明网络与写盘。预览、拒绝与按当前前缀重推导后接受的协议检查，见 [预览后由人选择的协议验证](preview-accept.md)。

参考路径不使用 `Lift`。它用稳定格子身份找当前位置，并从初始状态重放历史；几何布局由记录中的稳定身份重建，局部操作重放实际写集，色板重放已知合并。该路径帮助发现“坐标映射算法与自己比较”的假验证，但仍共享明确写下的首版支持策略。源码中的坐标公式另有真实操作检查。

| 不变量 | 本轮检查的含义 |
|---|---|
| NoSilentOverwrite | 接受集合必须属于独立参考判定的安全集合，后续改过的格子不能被覆盖 |
| PreserveLaterEdits | 安全目标之外的当前格子连同版本与身份完全不变 |
| CorrectInverse | 支持范围内不得漏掉安全格；恢复前像完整配对并递增版本。无冲突时，颜色与 completed 的整图等于省略 k 的已提交效果重放；有冲突时比较安全子集 |
| ColorDoneConsistency | 空格不能被标成完成。注意这一个格式不变量不能抓住全部完成标记恢复错误 |
| ConflictReported | 每个拒绝项都有冲突与理由，不能吞掉裁剪区后返回全部成功 |
| ABADetected | 即使当前颜色与 completed 恰好等于旧 after，只要中间版本变过，就报告冲突 |
| TypeOK | 尺寸、颜色、完成标记、版本及参考身份唯一性合法 |

## TLC 实测结果

最终 32 个配置全部符合各自预期。14 个正向配置通过，13 个覆盖或诊断配置到达指定见证，5 个故意错误变体找到指定反例。主探索实际生成 266625 个状态，134295 个不同状态，深度 5，exit 0。正向穷举界限是最多 4 条历史操作；定向组合路径含 5 条操作，深度 6。

完整逐项表与仓库布局复测见 [形式验证说明](formal/README.md#selectiveundo-扩展模型)，[精简证据](formal/evidence/SelectiveUndo-layout-recheck.txt)保留生成数、不同状态数、深度、退出码及模型哈希。各配置摘要另记配置与 JAR 的 SHA256。不要把重叠的配置状态数相加，也不要把不同状态数当成产品测试用例数。

TLC 是 2.19，工具发行标签 v1.7.4，Java 17.0.13。每次 1 worker，seed 20261112，fp 0。本轮是有限穷举，不是任意图纸与任意长历史的数学证明。见证和负例的 exit 12 是预期命中不变量，而非运行失败；它们在命中时提前结束，深度不能解读成遍历了完整状态空间。

### 五个错误变体

| 配置 | 最短定向路径与失效点 |
|---|---|
| SelectiveUndoNegativeValueABA | Agent 把格 1 改为 B，人擦空又画回 B。值比较误认未修改，覆盖人的版本。NoSilentOverwrite 在深度 5 失败 |
| SelectiveUndoNegativeNoCoordinateMap | Agent 改格 1，90° 旋转后此格到新索引 2，人改另一格，再撤 Agent。不组合坐标时在旧索引检查版本，漏掉本来可安全恢复的格。CorrectInverse 在深度 5 失败。这条轨迹展示漏恢复，不展示错格覆盖 |
| SelectiveUndoNegativeColorOnly | 初始 A、completed=true，Agent 画 B 后标记 false。只恢复 A 会留下 false；格式仍可合法，但逆操作不等于前像。CorrectInverse 在深度 3 失败 |
| SelectiveUndoNegativeHiddenConflict | Agent 改格 1 和格 6，再裁掉右列。格 6 已无目标；错误实现只恢复格 1，隐瞒格 6 并称全部成功。ConflictReported 在深度 4 失败 |
| SelectiveUndoNegativePaletteGuess | A 与 B 都合成 A，错误“逆”把所有 A 猜成 B，连原本就是 A 的格 1 都变了。CorrectInverse 在深度 3 失败。变体只隔离测试颜色猜逆，并不是完整的色板字典切换实现 |

这些是拟议协议的故意错误模型，不是 main 已实现的选择性撤销漏洞。main 尚无这一功能。

### 不是“什么也不做就通过”

`SelectiveUndoWitnessRotate`、`SelectiveUndoWitnessFlipH`、`SelectiveUndoWitnessFlipV` 确认变换后真的恢复了格子，并保留不相关人工编辑。`SelectiveUndoWitnessCrop` 确认同时出现保留区恢复与删除区冲突。`SelectiveUndoWitnessChain` 确认 rotate、flip、crop 连续组合后发生部分恢复。`SelectiveUndoWitnessPalette` 确认局部操作遇换板冲突，`SelectiveUndoWitnessPaletteInverse` 确认换板自身被拒，`SelectiveUndoWitnessABA` 确认相同值的新版本被识别。还有制作标记恢复、跨项目拒绝以及处理两个目标操作的见证。

## 实现必须共享的记录

所有改变 Project 的入口都必须产生记录，或产生显式“不支持自动恢复”的屏障。不能让某个 UI 按钮偷偷跳过版本与日志，再假设其他操作的撤销仍安全。

| 记录内容 | 必要字段及用途 |
|---|---|
| 事务身份 | projectId、projectEpoch、opId、author、kind、baseRev、commitRev、补偿时的 inverseOf。作者与时间只用真实来源，不捏造 |
| 局部前后像 | 实际写集内每格的 before 和 after，二者都含 colorId 与 completed，保存 beforeVersion 和 afterVersion |
| 坐标历史 | coordinateEpoch、旧新尺寸、每个结构操作的正向坐标映射、局部逆映射的定义域。删除格明确记无目标，不复用失效位置 |
| 色板历史 | 旧新色板内容或不可变版本、paletteEpoch、完整 sourceColorId 到 targetColorId 表、null 的处理。不能凭显示 RGB 近似重算旧映射，也不能丢命名空间 |
| 被删除的数据 | crop 的区域与偏移、被删格子的配对前像；用于预览或以后撤结构操作，不自动塞回当前尺寸 |
| 恢复决定 | accepted、conflicts、逐格原因、预览对应 revision、独立 compensationOpId。部分恢复要跟踪未解决格子，不把整个目标一笔标成完成 |
| 快照与日志 | 基线快照、内容哈希、连续操作前缀及版本水位。普通撤销、重做、人工笔画和 Agent 补偿共用协议；恢复旧值不恢复旧版本 |
| 条件性语义，若产品需要 | fill 的区域与读依赖、replace 的颜色谓词读依赖、选择区等。若承诺重执行原命令的语义，读依赖也是冲突输入 |

完整前快照适合恢复基线与生成预览。逐格前后像、映射和版本决定自动补偿范围。两种记录可以同时存在。

## 意外发现与先前说法的修正

- 可逆性不等于选择性撤销安全。旋转是双射，但撤销“之前的局部操作”和撤销“旋转本身”不是同一个证明。后来又裁剪或做另一结构操作时，还涉及尺寸与顺序。首版不自动撤结构事务。
- 多对一换板也不等于以前的局部前像永远不可用。有完整 before 与正向映射 F 时，可以计算 F(beforeColor) 形成候选，未必需要 F 的逆。但完成标记、版本因果、当前色板合法性及后续编辑必须另证。本轮选择保守屏障，没有证明这条优化。
- 单射色板映射只在其像集上有逆。如果后来人用了目标色板中不在像集的新色，仍无法翻回旧色板。单射并不是自动放开的充分条件，本模型也没验证这个扩展。
- 源码 `map-palette` 保留 completed；源码 `paint` 只在颜色真正改变时清 completed。合色会让 paint 变成无变化，所以颜色映射与 paint 不能机械地交换。这已用实际 handler 验证。
- “去掉目标后重放”必须说明重放的是效果还是命令。仅靠逐格写版本无法识别全部 fill 与 replace 的语义读依赖。本轮新增见证揭示了这项契约缺口，没有掩盖它。

- [ ] 测试部分恢复后重试未解决格子、撤补偿操作与重做，以及两个目标在同格交叠。当前模型每个目标只处理一次，不证明这些产品行为。

- [ ] 若产品选择“命令意图重执行”契约，先补 read-set 与语义依赖模型，不能把当前 CorrectInverse 当作通过该验收。

模型的其他界限：网格最多初始 6 格；只有两种非空抽象颜色；Explore 的 Paint 选集限于当前首尾格及其组合，Replace 可覆盖更广区域，Done 限首尾格。主探索最多 4 操作，不穷举所有历史。crop 仅删右列，不包括新增格。模型不证明 RGB 距离、文件系统、崩溃恢复、权限政策、渲染、性能或可用性。版本无重用是假设，不是主应用已满足的事实。
